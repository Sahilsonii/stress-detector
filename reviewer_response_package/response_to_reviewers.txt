RESPONSE TO EDITOR AND REVIEWERS

Dear Editor,

Thank you for the opportunity to revise our manuscript. We have carried out a
substantial revision that directly addresses every point in your Major
Revision letter, and in the process strengthened the work further than the
letter alone required: the keystroke-dynamics module has been rebuilt end to
end on a real, verifiable dataset with a fully reproducible training
pipeline, all reported metrics have been re-derived from the actual
evaluation artefacts (not re-typed by hand), and every figure in this
package was generated directly from those artefacts.

We believe the revised manuscript is materially stronger: the facial model
results, which were already solid, are now traceable line-for-line to
`results/{Model}/metrics.json` and `classification_report.txt` in the
repository; the keystroke model is no longer an unsupported claim but a
trained, evaluated, and reproducible Random Forest classifier; and the
comparison figures your team will see in the resubmission are generated by
code that reads those same files directly, closing the gap between what the
paper claims and what the repository actually contains.

Below we respond to each of your eight points individually. All referenced
numbers are backed by files in this package (`facial_results/`,
`keystroke_results/`) and in the GitHub repository.

--------------------------------------------------------------------------
1. "Clarify how 'stress' labels were created"
--------------------------------------------------------------------------
We have added explicit label-generation methodology for both modalities.

Facial: the FER2013-derived binary mapping (negative-valence + neutral =
Stressed, positive-valence = Not Stressed) is now explicitly flagged in the
Methodology as a proxy label, not a clinical diagnosis, with a pointer to
the Limitations discussion.

Keystroke: this required a deeper fix than a clarifying sentence. We
discovered during revision that the originally reported keystroke features
(backspace count, total words typed, error rate) do not exist in the public
CMU Keystroke Dynamics Benchmark dataset our citation points to -- that
dataset contains only fixed-password hold-time and inter-key latency
measurements. We have rebuilt the keystroke pipeline from scratch on the
actual public dataset (51 subjects x 400 repetitions of a fixed password),
engineering five timing-based features (hold_mean, hold_std, flight_mean,
flight_std, total_duration) and defining stress-proxy labels as each
repetition's deviation from that participant's own personal typing
baseline -- explicitly decoupled from the features fed to the classifier,
to avoid label leakage. This rule, and why it was chosen, is now fully
documented in the revised Methodology (see keystroke_results/metrics.json
for the exact formula and threshold).

--------------------------------------------------------------------------
2. "Do not overclaim multimodal fusion performance"
--------------------------------------------------------------------------
We agree the single-screenshot 93.7% figure was insufficient evidence and
have removed it as a standalone claim. [Status: we are in the process of
collecting a small paired facial+keystroke evaluation from consenting
author-participants using a new purpose-built session-capture tool
(`keystroke_timing_logger.py`), to replace the single example with a real
aggregate result and an honest small-N caveat in Limitations, per your
suggested fallback of describing the system as a demonstrated prototype
where full benchmarking is not yet available. This section will be
finalized in the resubmission.]

--------------------------------------------------------------------------
3. "Correct inconsistencies in the reported metrics"
--------------------------------------------------------------------------
We traced every reported number back to its source file and corrected three
concrete errors:

  - The sentence crediting MobileNetV2 with "the highest accuracy... 0.94"
    conflated its AUC (0.94, correctly the highest of the three models)
    with its accuracy (0.85). This is now stated correctly in both
    directions (see facial_results/MobileNetV2/metrics.json).

  - The Discussion's ResNet50V2 confusion-matrix narrative (previously
    citing 3,240 / 166 / 1,102 / 614 on an implied 5,122-sample set) did
    not match the actual evaluation, which was run on the full 13,479-
    sample validation set. It has been replaced with the real counts:
    TP=8,560, FP=466, TN=3,388, FN=1,065 (facial_results/ResNet50V2/
    classification_report.txt) -- and this correction actually reverses a
    conclusion in our favour: the real numbers show ResNet50V2 misses
    FEWER stress cases than MobileNetV2 (11.06% vs. 16.40% miss rate),
    consistent with Table 5's recall values, which needed no correction.

  - The RF-vs-Decision-Tree comparison sentence was previously truncated
    mid-sentence and cited an unsupported 76.45% baseline. It now reports
    the real, freshly-trained Decision Tree baseline (72.00% accuracy)
    against the real RF result (73.65%), a reproducible 1.65-point gap,
    alongside 5-fold group-aware cross-validation of 78.78% +/- 2.52%
    (keystroke_results/metrics.json).

All comparison figures (facial_results/comparison/*.png) are now generated
by code that parses the real confusion matrix out of each model's
classification report, rather than reconstructing an approximate one from
precision and recall -- a latent bug we found and fixed in
`generate_comparison_report.py` / `regenerate_reports_only.py` while
verifying the numbers above.

--------------------------------------------------------------------------
4. "Moderate claims about workplace and clinical use"
--------------------------------------------------------------------------
We have softened language in the Abstract and Conclusion that implied
validated real-time occupational deployment, and added an explicit
statement that the system has not undergone workplace field testing or
clinical/physiological validation. The Future Directions section already
called for this validation; we have made the current absence of it more
visible earlier in the paper rather than only in the limitations.

--------------------------------------------------------------------------
5. "Describe the custom dataset in detail"
--------------------------------------------------------------------------
Per Reviewer 2's confirmation in the prior round, the Ethics/Consent
declarations (participant count, exemption rationale, written consent for
publication) already satisfied this point and are unchanged.

--------------------------------------------------------------------------
6. "Clarify threshold optimisation"
--------------------------------------------------------------------------
The keystroke threshold sweep is now explicit about methodology: theta is
selected on the validation split only (F1-maximising), and reported
separately from the held-out test-set evaluation at that chosen threshold,
so no threshold was tuned on the same data used to report final performance
(keystroke_results/threshold_table.json shows the full validation sweep;
keystroke_results/metrics.json separates default-threshold and optimized-
threshold test results explicitly).

--------------------------------------------------------------------------
7. "Improve comparison with prior work"
--------------------------------------------------------------------------
We have added an explicit caveat immediately after the comparison table
stating that the listed studies differ in dataset, modality, sample size,
and validation protocol, and that direct accuracy comparison should be
read with that in mind -- only the sensor-free deployment profile is
directly comparable across systems.

--------------------------------------------------------------------------
8. "Revise the language and structure"
--------------------------------------------------------------------------
We have corrected grammar and clarity issues in every passage touched by
the numerical corrections above (see manuscript_corrections.md for the
full list of before/after text). A broader copy-edit pass of untouched
sections is available on request if the editorial team would like it
before typesetting.

--------------------------------------------------------------------------
Summary
--------------------------------------------------------------------------
We are confident this revision addresses the letter's concerns
substantively rather than cosmetically: the keystroke modality now rests on
a real, reproducible, publicly-documented dataset and training pipeline
instead of an unverifiable claim; every metric in the paper can be traced
to a file in the repository; and the one item still in progress (a properly
benchmarked fusion result) is being completed with real data rather than
being patched over. We believe this puts the manuscript in a strong
position for acceptance and thank the editor and reviewers again for the
careful reading that identified these issues.
